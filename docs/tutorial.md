# 新手教程（新手引导）自动化 —— 设计与待校正清单

> 状态：**仅完成代码与资源校验**，没有教程实机截图、没有真机验证。
> 所有阶段划分、ROI、文案判断均**基于经验推断**，必须在拿到教程截图后逐条校正。

## 1. 定位与边界

- 任务入口：`interface.json` → 任务「新手教程」→ 节点 `新手教程_入口`。
- 本任务**不启动游戏、不登录**：前提是游戏已经停在教程任意页面（登录后的开场引导）。
  注意：新判据（§8、实现见 §11）要求「交接语 + 主界面底部栏在场 + 无手指」同时成立才算成功，
  **不是"一到主界面就成功"**——0-1~0-3 打完时功能栏已全开但仍有手指引导，任务会继续推进。
- 只做「推进 + 保守点击」。有副作用的操作仅限教程强制段：建角色（输入昵称）、编队拖拽、
  以及弹窗明写「本次构建不需要任何费用」的补给站十连；任何真实付费/消耗按钮一律不点（见 §5）。

> **已被 §8 取代**：成功出口改为「交接语 + 主界面功能栏全开 + 引导手指消失」，实现见 §11。
> 下面保留的是第一版「OCR 补给站」单出口记录，只作历史对照。

`新手教程_推进` 的 `next` 前两项：

## 3. 失败出口（不无限点击）

| 节点 | 触发条件 | 行为 |
|---|---|---|
| `新手教程_超时失败` | `新手教程_调度` 达到 `max_hit=600`（按 0-1~0-3 实测耗时预留×2）；或 `安全区盲点` 60 次 + `新手教程_空转等待` 540 次全部用尽后 next 全空 | `arena_atomic` fail，日志写明「超出轮次预算仍未同时满足交接语 + 功能栏全开 + 无手指」 |
| `新手教程_危险中止` | 命中付费/消耗类文案，但整屏找不到任何取消/关闭/跳过/稍后入口 | `arena_atomic` fail，日志写明「按安全红线中止，未点击任何购买类按钮」 |

pipeline 协议没有墙钟计时器，上限用「轮次上限 × 单轮节拍」近似：
每轮约 0.2s 延迟 + 1.0s 稳定等待 + 1.2s 后置延迟 ≈ 2.5s，600 轮约 25 分钟（= 教程实测耗时 ×2 的余量）。
**实机后必须按实测节拍校准 `max_hit`。**

## 5. 安全红线的实现方式

1. **先检测、后点击**：`新手教程_推进` 的 `next` 顺序把 `新手教程_危险弹窗检测` 放在所有点击类节点之前。
   该节点 `action: DoNothing`，全屏 OCR 只做识别。
2. **命中即只走退出路径**：检测到「购买 / 充值 / 抽卡 / ¥ / $ / 消耗 / 体力药」后，只允许
   `新手教程_危险弹窗_退出`，其 `expected` 是安全词白名单：取消 / 稍后 / 以后再说 / 暂不 / 放弃 / 关闭 / 跳过 / 返回。
3. **找不到安全入口就失败**：`新手教程_危险弹窗_退出` 的 `on_error` 指向 `新手教程_危险中止`，
   用 `arena_atomic` 的 fail 分支明确报错，不继续盲点、不点「确定」。
4. **数值选择默认取消**：`消耗`、`体力药` 已在危险词表里，因此「是否消耗道具」类弹窗一定走退出路径。
5. **盲点排在最后**：`新手教程_安全区盲点` 是 `next` 的最后一项，只有全部显式文案都没命中才会执行；
   且 `max_hit=60` 封顶，避免在未知页面无限乱点。
6. **点击目标永远是识别框**：所有 Click 都不写 `target`，默认点识别框中心。

已知残余风险：若某页面出现价格元素但 OCR 没读到危险词，而所有安全词也未命中，
则可能退化到安全区盲点。因此安全区 ROI 被刻意收窄到画面中上部（见下），避开底部购买确认区。

## 8. 教程结束判据（2026-11-03 实机校正，权威）

> 本节替代 §2 的「OCR 补给站」单出口判据。原判据只能证明"已到主界面"，不能证明"教程已结束"。

### 主判据（必须）

0-4 编队页出现交接语 **「接下来就交给总队长判断了。」** 之后：

- 引导手指（手形图标）与引导气泡**全部消失**；
- 后续操作**不再出现任何新引导**（连续进入任务页 / 补给站 / 章节页均无蒙层）。

### 辅判据（同时满足更稳）

主界面功能栏**全开且无蒙层**：

- 底部：`基地`、`任务`、`编队`、`队员`、`构建`、`补给站`、`出击`
- 左侧：`勘探指南`、`周期特训`、`物资调配`、`午夜对乐`
- 右上：`满馈赠礼`、`首充奖励`、`活动`、`邮件`

> **落地口径（2026-11-03）**：不要求上述每一项都命中。这些入口会随账号状态收缩/消失，
> 全量命中会把"教程已结束"误判成失败。pipeline 只硬检「底部栏在场」+「无引导手指」，
> 其余仅作人工排查线索。详见 §11.3「为何不用全量功能栏」。

### 反例（不得作为必要条件）

- **E1「教程完成 / 教程结束」弹窗**：全程**没有出现**。不要把"找到完成弹窗"写进 pipeline 的成功条件，否则永远等不到。
- **章节阶段奖励 / 补给站免费十连**：属于正常玩法奖励，不是"教程奖励"，不能当结束判据。
- 只出现"功能栏全开"但仍有手指引导 → **未结束**（0-2 后就是这种状态）。

## 11. 落地实现（3 文件）

> 2026-11-03 按 §8 判据 + §9 步骤表落地。坐标一律来自 1280×720 原始帧，来源帧写在每个节点的 `next_doc`。

### 11.1 文件与职责

| 文件 | 节点数 | 职责 |
|---|---|---|
| `pipeline/base/新手教程.json` | 16 | **调度层**：hub、结束判据链、安全闸、剧情跳过、兜底与失败出口 |
| `pipeline/base/新手教程-引导.json` | 63 | **引导段**：9 个阶段闸 + 阶段内步骤 + 8 个阶段跳过 + 公共出口 |
| `pipeline/base/新手教程-战斗.json` | 17 | **战斗段**：HUD 判据、选敌、施法、投射、终技、胜利、解锁 |

三份文件共用同一个节点命名空间，跨文件引用直接写节点名（不写 `[JumpBack]` 跨文件也行，本实现只在复用 `通用.json` 节点时加 `[JumpBack]`）。

### 11.2 调度层结构

```
新手教程_入口          一次性完成探针：已结束→直接成功，否则→调度
   └→ 教程_结束复核 ──(不满足)──→ 新手教程_调度（hub，max_hit=600）
新手教程_调度  next 顺序：
  教程_交接语 → 新手教程_危险弹窗检测 → [JumpBack]公告/促销/同意
  → 9 个阶段闸（引导）→ 战斗_进场/胜利/胜利_模板/解锁关闭
  → 引导_主界面入口 → 剧情跳过/点击继续/继续 → [JumpBack]获得物品/确认
  → 新手教程_安全区盲点（max_hit=60）→ 新手教程_空转等待（max_hit=540）
```

- **`max_hit=600`**：整条教程的轮次预算（按 0-1~0-3 实测耗时预留×2，覆盖三场战斗 + 全段引导）。
  600 次耗尽后 hub 的 next 全部失效 → 本轮扫描 20s 超时 → `on_error` → `新手教程_超时失败`。
- **预算终点是明确失败**：盲点 60 次 + 空转 540 次用完即预算耗尽，不会静默结束。
- **阶段分层而非扁平扫描**：hub 只扫约 25 个全局节点 + 9 个阶段闸；进闸后只扫该页 5–8 步；
  阶段末尾用 `引导_回调度` / `战斗_回调度` **立刻返回**，不闷等超时。

### 11.3 结束判据链（§8 的落地）

| 节点 | 判据 | 关键参数 |
|---|---|---|
| `教程_交接语` | OCR「交给总队长判断」 | `roi [380,295,700,130]`，`threshold 0.3`，`max_hit 1`，`pre_wait_freezes {1s, 0.95}` |
| `教程_结束复核` | `And` 底部栏在场（`NavMainBottomBar`，OCR `roi [493,580,773,137]`，`expected` 为空＝栏内有任意文字） | `pre_wait_freezes {3s, 0.95}`，`on_error → 新手教程_调度` |
| `教程_无手指` | `TemplateMatch` `Tutorial/Finger.png`，`inverse` | `roi` 全屏，`threshold 0.85`（自检 1.000/0.887，负例 ≤0.676） |
| `教程_完成` | `DirectHit`，终端节点 | 唯一成功出口 |

**为何不用全量功能栏**（2026-11-03 调整，勿回退）：
原 `all_of` 要求 `NavMainBaseText` / `NavMainTaskText` / `NavMainFormation` / `NavMainBuild` /
`NavMainSupplyStation` / `NavMainSortie` 六项全部命中。这类入口会随账号状态**常驻收缩或消失**
（首充奖励领完、活动结束、功能解锁前后图标不同），只要缺一项，`And` 就永不成立——
教程已经走完也会被误判成超时失败。现改为**单条硬判据** `NavMainBottomBar`（栏内有任意文字即算在场）
+ 下游 `教程_无手指`，六项 OCR 只作排查线索、不参与 `all_of`。
代价是判据变宽（底部栏在场且无手指即成功），但两个条件合起来已足够区分"教程中段有手指"与"教程已结束"。

**结束判据的触发点只有四处**：`新手教程_入口`（一次性探针）、`教程_交接语`（命中后）、
`引导_回调度`、`战斗_回调度`。

> **为什么不把 `教程_结束复核` 放进 hub 的 next 首位**：0-2 之后主界面功能栏**就已经全开**，
> 而手指引导还在。若 hub 每轮先复查：命中 → `教程_无手指` 失败 → `on_error` 回 hub → 再命中，
> 形成空转，所有阶段闸永远轮不到。改成"入口/交接语/回调度"触发后，同一条 And 判据不变，
> 但不会阻塞推进。

### 11.4 失败容错

- 每步 `timeout` 6–10s；点击后 `post_delay` 0.6–1.2s。
- 每个阶段配 `教程_跳过_<阶段>`（`DirectHit` → `引导_回调度`，`timeout 5000`，`on_error → 新手教程_超时失败`）。
  `on_error` 只做"跳过这一步"，不做重试风暴。
- 单步 `max_hit ≤ 3`，两类**显式例外**（都不是无脑重复）：
  - `引导_出击` / `引导_开始战斗` / `引导_开始行动` = 4（教程要 0-1~0-4 共四次出征；开始战斗第 1 次只出气泡，要再点一次）；
  - `战斗_选敌_红框` / `战斗_选卡` 等战斗循环节点 = 6–8（一次战斗要多次施法）。
- 所有节点都有出口：成功走步骤链，失败走 `on_error`，不允许"无 next 无 on_error"的死角。

`And` 的 `all_of` 字符串项只取该节点的**识别算法和参数**，节点级 `inverse` / `anchor` 不生效——
所以"手指消失"不能塞进 `And`，只能做成下游串接节点（这也是 11.3 那条链的由来）。

**inverse 日志判读（2026-11-03 实跑）**：`inverse: true` 的 TemplateMatch，binding 上报的
`reco.hit` 是 **inverse 之前的原始匹配值**，不要当成节点失败。负例实跑
`教程_无手指` 日志为 `hit=False`，但任务继续走到 `教程_完成`、`job.succeeded=True`；
同帧 `Tutorial/Finger.png` 原始分 **0.5009**（阈值 0.85），inverse 后成立。
判读口径：看 job 是否走到下游 / 节点是否 completed，`reco.hit` 只用于确认模板在不在场。
台账见 `docs/问题登记.md` P-013。

**编队一律先切「平面」再识别**：进入编队阶段先走 `引导_切平面`（OCR「平面」标签 → 点击 →
`引导_切平面_确认` 用 ColorMatch 验证「立体」半区变暗），之后的格子定位与长按拖拽全部在平面模式的
2D 网格上做。原因：立体是 3D 摆位，角色位置与朝向会变，格子坐标不可靠；平面是固定 2D 网格。
阈值取自 1280×720 原始帧 `T4_10_slot_A.png` 实测（立体态该半区 669 px 落在 RGB
`[95,92,96]~[140,138,140]`，平面半区同区间 0 px），**不按缩放图换算**。
