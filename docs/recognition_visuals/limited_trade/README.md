# 限时贸易所购买识别说明

进入限时贸易所后，先在右上角 `[1080, 5, 200, 70]` 区域用 OCR 读取星币总数；
只接受 1～12 位纯数字，并要求连续两次读数一致。该区域不读取商品卡片下方价格。
任务设置顶部的“星币低于多少时不购买任何物品”默认是 `200000`。稳定读数严格小于
用户输入值时，任务不扫描商品、不点击购买并以成功状态结束；读数等于下限时仍继续。

限时贸易所商品节点继续使用原有全屏 OCR 区域 `[0, 0, 0, 0]`，点击目标仍为 OCR 识别文字自身。

任务开始时，自定义动作 `limited_trade_setup` 读取当前 MFA 任务设置并生成白名单：

- 素材：原素材及 `初级硅化剂`、`进化之息`、`涅槃凝胶`；
- 武装技能训练：技能书Ⅰ/Ⅱ/Ⅲ分别识别 `武装技能训练`、`技能2`、`技能3`；
- 模块：`稀有模块`、`定制模块`；
- 芯片箱：由已勾选的芯片类型与 R4/R5 组合成 `R4连击芯片箱` 等 OCR 文本。

进入贸易所后先全屏 OCR 当前页面，再按参考坐标 `(1080,360) -> (820,360)`
向左拖动 260 像素并再次全屏 OCR。第二页结果与第一页按商品名去重；先购买第二页
可见商品，再用完全相反的拖动回到第一页，仅购买第一页独有商品。

外层状态识别仅负责去重和页面切换；每件商品仍交给 `LimitedTradeProductOCR`
以原有 OCR 方式和全屏区域定位，点击坐标仍来自 OCR 结果。

若全部分类都关闭，任务直接进入完成分支，避免空白 `expected` 被解释为识别任意文字。

## 购买策略

每个已开启品类先根据两页 OCR 结果生成候选商品，再应用自己的策略：

- `购买所有本商品`：保留该品类全部候选；
- `仅购买一个本商品`：按视觉行从上到下、每行从左到右保留第一个；
- `当没有其他满足要求商品时购买本商品`：正常策略合计为零时，从所有兜底品类
  的候选中按相同空间顺序购买一个。

默认值为：素材兜底、技能书仅一个、模块兜底、芯片箱全部购买。

同一轮全屏 OCR 中出现的“售罄/已售罄”会按横坐标及商品名下方的
纵向距离绑定到对应卡片；被绑定的商品在制定购买计划前剔除。只要页面
出现任一售罄标记，日志就记录本轮已执行过限时贸易所购买操作。两页均无
可购买候选时，以成功状态结束并输出“当前无符合要求物品，未执行购买操作”。

星币区域见 `coin_balance_ocr.svg`；商品可视化区域见 `limited_trade_fullscreen_ocr.svg`。

## 芯片箱购买后的筛选

芯片箱购买完成后，流程会优先识别“获得物品”弹层，再执行：

1. 点击弹层中央的单枚芯片，等待详情稳定显示后再额外等待 1 秒；
2. R4 芯片不读取词条，也不修改锁定状态（保持游戏原有状态）；
3. R5 芯片复用 CF3 方案读取四行主/副词条，符合方案且主词条不是 3 级时点击一次锁键；
4. 主词条 3 级由游戏自动上锁，流程不点击；不符合方案的 R5 也不点击；
5. R5 点击后等待 1.2 秒，不做锁状态复核、不二次点击；R4 不点击。两者随后都先点外围关闭详情，确认回到获得物品层后等待 0.6 秒，再第二次点击外围返回商店。

R5 等级 OCR 会按同行合并文字；游戏中较窄的“等级 1”若被拆成
`等级.` 与右侧 `④/＋`，仅在两段位于同一行时按 1 级处理。若多次读取后
仍无法组成四行完整详情，则不点击锁键，执行同样的两次外围退出并继续任务，
避免单个芯片识别不稳定导致整个限时贸易任务失败。

新增区域、点击点与退出路径见 `limited_trade_chip_reward.svg`。坐标均为
1920×1080参考坐标，运行时按实际分辨率等比换算。

## 待办：同名不同价（用户 2026-11-11 明确「之后排上」，当前不动代码）

**已查明的前提**

- 商品识别 `LimitedTradeProductOCR` 是全屏 OCR（`roi [0, 0, 0, 0]`），只取名字文本、
  点击名字框中心；页面上没有把某一档价格绑到某张同名卡的能力。
- 全屏 OCR 本身已经能读到货架上的价格数字，缺的只是「名字框 → 价格框」的绑定。
- 罕见星尘区 / 角斗场 / 镜像竞技已改为「名字 + 价格」匹配（`agent/store_purchase.py`，
  白名单条目支持可选 `price`）；限时贸易所仍是纯名字匹配，同名不同价会串档。

**需要的帧（1280×720 原始帧）**

1. 限时贸易所货架第 1 页（首屏）；
2. 左滑 260 像素后的第 2 页；
3. 带折扣标签的卡片（如 `-30%`）；
4. 售罄 / 已售罄卡片；
5. **同名不同价的真实样本**（关键，用于确认两档价格与两个名字框的对应关系）；
6. 长名字 / 名字换两行的卡片；
7. （可选）点开商品后的详情弹窗。

**要量的东西**

- 价格数字的 ROI，或「名字框底边 → 价格行」的纵向偏移（含容差上限）；
- 货币图标宽度（用于把图标与价格数字切开，避免把图标并进数字）；
- 折扣标签与价格的相对位置（折后价与划线原价谁在左、谁在右）。

**接进来之后还要定的面板交互**

- 现状：`assets/interface.json` 的限时贸易选项按品类给策略（`购买所有本商品` /
  `仅购买一个本商品` / 兜底），芯片箱再按箱型与 R4/R5 品质组合，没有「名字 + 价格」
  这个勾选维度。
- 需要先定：同名多价时是「面板仍按品类勾选，代码内取某一档」，还是后面给白名单加
  `price` 档位、判不出即跳过（与三家店的 fail-closed 口径一致）。定之前不改
  `interface.json`。
