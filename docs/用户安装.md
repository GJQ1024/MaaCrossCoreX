# 用户安装指南

本工具用于在 MuMu 模拟器上自动完成《交错战线》的日常任务。
两种分发形态二选一，**开箱即用选模式 B，已有壳选模式 A**。

---

## 前置条件

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10/11（64 位） |
| 模拟器 | **MuMu 12**（MuMuPlayer-12.0），实例原生分辨率 1280×720 |
| 游戏 | 《交错战线》B站服，已登录并能进入主界面 |
| .NET 运行时 | 模式 B 自带；模式 A 需要 .NET 10 桌面运行时（壳自带，一般无需额外安装） |

> 实例原生分辨率必须是 1280×720（`MuMuManager setting -v 1 --all` 里 `resolution_mode=tablet.2`）。
> 若不是，pretask 默认只读并告警；仅带 `--apply` 时才执行「竖→横→reset」三步切换，失败只告警不中止（帧级硬闸见 `docs/device.md`）。

---

## 安装

### 模式 B（推荐，开箱即用）

解压后直接双击 `MFAAvalonia.exe`。首次启动会自动安装 Agent 依赖（需联网一次，
或提前把 `deps/` 里的轮子放在同目录）。

### 模式 A（自备壳）

1. 先装好 MFAAvalonia 壳（从其 Release 下载，放到一个目录，例如 `MFA/`）。
2. 把模式 A 压缩包里的**所有内容**（`resource/`、`scripts/`、`agent/`、
   `python/`、`deps/`、`interface.json` 等）**合并**到壳目录里（覆盖同名文件）。
3. 双击壳目录里的 `MFAAvalonia.exe`。

> 模式 A 不含 MaaFramework 原生库（`runtimes/`），这些由壳提供；
> 不要把模式 A 单独运行，必须和壳合并。

#### 模式 A 合并实机样例（2026-11-02 验证通过）

环境：干净 MFAAvalonia `v0.1.3` 壳 + 模式 A 产物（`v0.5.11`），MuMu 实例 <实例>（1280×720 横屏）。
连接目标由自动发现 + 包名校验确定，日志会打印实例名与端口。

合并方式：新建独立目录（如 `clean-shell/`）放壳的全部文件，再把模式 A 产物的
`resource/`、`scripts/`、`agent/`、`python/`、`deps/`、`default/`、`interface.json`
整体复制进去覆盖同名文件。随后直接启动壳跑任务「启动游戏」：

- 总耗时 **18 秒**，结束状态 **SUCCEEDED**，任务「启动游戏」完整走完。
- 关键节点（`logs/log-YYYYMMDD.log`）：
  1. `pretask` 第 1 步：`MuMu 与 ADB 已就绪`
  2. `pretask` 第 2 步：`预检通过：1280x720 bbox=1280x720 覆盖=1.0`
  3. `控制器检测完成（异步）`
  4. Agent：`[agent] maafw OK (v5.14.3)`
  5. Agent：`[agent] custom actions ready：订单_检查好友配置, 取下一单, 输入当前UID, 取下一待删好友, 删除登记完成`
  6. `连接状态变更：已连接`
  7. `任务已全部完成！(用时 0h 0m 18s)`

> **坑 1：必须用模式 A 包里的 `interface.json`，不能用开发版。**
> 开发版 `interface.json` 的 `agent` 字段为空、`pretask` 指向开发机 venv 绝对路径
> （如 `C:\...\sandbox\venv\Scripts\python.exe`）。合并后壳能启动、预检也能过，
> 但会在控制器初始化后直接退出，`logs/` 里没有 agent 日志可查。
> 模式 A 包里的版本用相对路径（`agent.child_exec` = `./python/python.exe -u ./agent/main.py`，
> `pretask.exec` 用 `../../python/python.exe`），才是可分发形态。
>
> **坑 2：`config/instances/default.json` 不要写死端口或实例 index。**
> `AdbSerial` 留空、`AdbDevice.Config` 里的 `extras.mumu.index` 保持 `null`，都是"自动"语义：
> pretask（`agent/ensure_mumu.py`）会自动发现所有在线 adb 目标，用 `pm list packages` 校验哪个装了交错战线，
> 再回填真实 serial 与 index，并在日志里打印实例名与端口。
> 不同模拟器端口规则不同、实例重启后端口也会变，写死端口在换实例/重启后就会失效——
> 典型表现是"连不上/控制器初始化失败"。只有确实不需要 MuMu 指纹时才把整个 `Config` 写成 `"{}"`。

> **`dist/clean-shell` 已废弃（2026-11-09）**：它是 2026-11-02 的一次性验证快照，
> 选设备逻辑还停在旧版（按实例顺序自动挑），**不要用它跑任务**；需要验证模式 A 时按本文重新合并。

## 使用

1. **先手动打开 MuMu 12 里的目标实例（本项目是 <实例>），等游戏停在主界面**——自动化**不会替你开模拟器**；
   未检测到实例运行时会中止任务并提示，不会自动 launch。
2. 双击 `MFAAvalonia.exe` 打开壳。
3. 在「任务」里勾选要执行的任务，点「开始」。
4. 启动时会自动跑两步预检：自动连接 MuMu → 校验画面是 1280×720 满屏横屏。
   预检通过才会开始跑任务。

## 常见报错

### 1. `pretask '设备横屏预检' exited with code 2`（预检失败）

画面不是 1280×720 满屏横屏。常见原因与处理：

- **窗口被最小化或遮挡**：把 MuMu 窗口恢复到前台、不要最小化，重试。
- **实例分辨率不是 1280×720**：`MuMuManager setting -v 1 --all` 确认
  `resolution_mode=tablet.2`；若不是，在 MuMu 设置里改回 1280×720。
- **安卓侧 wm size 被改坏**：在工具里跑 `adb shell wm size reset` 清除 Override，
  或重启 MuMu 实例。

预检日志在 `logs/pretask_landscape.log`，里面会写清楚是尺寸不对还是被压扁。

### 2. `找不到设备` / `adb 连接失败`

- 确认 MuMu 12 已启动且目标实例在运行、游戏已安装。
- 本工具会自动发现所有在线的 adb 目标，逐个用 `pm list packages` 查交错战线（`crosscore`），
  唯一命中的实例才会被选中；日志会打印候选、查包结果和最终选定的实例名与端口。
- 若日志报"未找到安装了交错战线的实例"，说明目标实例没装游戏或 adb 没连上；
  多个实例都装了时，日志会列出全部候选，可用环境变量 `ADB_SERIAL` 指定其中一个。
- 不同模拟器端口规则不同，不要手工写死端口。

### 2.1 `未找到可用的 adb.exe（不回落到裸 adb）`

模拟器装在**非默认盘符或自定义目录**（例如被改名的 `D:\YXCrossCore-12.0`）时可能出现。
日志会把已检查的位置逐条列出，并按优先级给出三种修法，任选其一填完重跑任务即可：

1. 壳首页「当前控制器」为 ADB 时，点「自定义」打开 Adb 编辑器，在 **「Adb路径」** 填
   `adb.exe` 的**完整路径**（例如 `<本机路径>`；只写 `adb` 无效）；
2. 设置环境变量 `MUMU_ADB=<adb.exe 完整路径>`；
3. 只知道安装目录时，设置环境变量 `MUMU_HOME=<MuMu 安装根目录>`，
   工具会在该目录内按布局自动找 `shell\adb.exe`、`nx_main\adb.exe`、
   `nx_device\*\shell\adb.exe`、`platform-tools\adb.exe` 等，不依赖子目录名。

从 v1.0.4 之后的版本起，**adb 定位失败不会中止任务链**：「启动 MuMu / 配置 ADB」与「设备横屏预检」
只记一条警告并跳过（壳已连接设备时后续任务照常跑）；需要排查时才用
`python scripts/pretask_landscape.py --check` 复现，该模式会以非零码退出。

### 3. `OCR 加载失败` / 模型相关错误

- 确认 `resource/model/ocr/` 目录存在且非空。
- 模式 A 合并到壳时，`resource/` 是整体覆盖的，不要只拷部分文件。

### 4. Agent 启动失败 / `maafw version mismatch`

- 首次启动会联网安装依赖；若离线，确认 `deps/` 目录里有 `maafw-*.whl`、
  `numpy-*.whl` 等轮子。
- 运行 `Install-Agent-Deps.bat`（Windows）手动重装依赖。

## 版本

界面右下角或 `interface.json` 里的 `version` 字段即当前版本号。
反馈问题时请附上这个版本号和 `logs/` 目录。

## 发版前检查清单

1. **壳版本的两处硬编码必须对齐。** 壳版本现在各写一份，改一处就要两处一起改：
   - `tools/install.py` 的 `MFA_VERSION`——写进打包产物的 `NOTICE`
     （`bundles MFAAvalonia ... version v0.1.3`）；
   - `.github/workflows/install.yml` 的 `env.MFAA_VERSION`——CI 真正下载并打进包的壳版本。
   两者不一致时，`NOTICE` 声明的版本和包里实际壳版本会对不上。当前先靠人工核对，不改 CI。
2. 重新构建 `dist/A` 与 `dist/B` 后，确认 `NOTICE` 里"壳来源"（`MAACrossCore/MCCAvalonia`）
   与"本项目源码"（`GJQ1024/MaaCrossCoreX`）两行地址仍然不同、没有被混写。
3. `deps/` 里只保留嵌入式 Python 实际会用到的轮子（当前 `maafw-5.14.3`、`numpy`、
   `MaaAgentBinary`、`strenum`）；旧版本轮子（如 `maafw-5.12.3`）会白占 20+ MB。
