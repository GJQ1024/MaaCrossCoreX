# 基建换班（红脸触发 → 整组切预设）

> 本文只记录**实测事实**与已落地实现。未实测内容一律标注「未实测」，不猜规则。

## 0. 开工前：先区分「游戏屏保」与「系统锁屏」

- 空闲后出现的是**游戏自己的屏保**（游戏 CG + 左下时钟/日期/电量 + 右下圆形刷新图标），前台仍是 `com.megagame.crosscore.bilibili`、`isKeyguardShowing=false`；`svc power stayon` 压不住它。
- 处置：轻点中性点 `(1200,400)` 或按一次 BACK，**下一帧复核**离开待机画面才算唤醒；若停在弹窗，按既有弹窗策略关闭。`KEYCODE_WAKEUP` + 上滑只用于真正的 Android 系统锁屏。
- 未唤醒就进面板会 OCR 不到「驻员状况」，误判为「界面不存在」。判据与证据见 `docs/项目规范.md` §8.1、`docs/问题登记.md` P-051。

## 1. 游戏事实（2026-11-05 实机）

### 1.1 驻员状况面板

- 入口：主界面左下「驻员状况」按钮 → 打开面板（`基建_驻员状况`，OCR roi `[54,554,176,89]`）。
- 行序固定：行星指挥部、能源发电站、挖掘矿场、原料交易所、合成工厂、研发中心、宿舍（最后一行）。
- 行高 139px（1280×720）；设施名在左列 x≈338–347，正文框高度 22。
- 每行右侧有「驻员预设」按钮（x≈973，中心相对设施名框 `+672,+4`）；**宿舍行没有该按钮**。
- 面板内**不显示**每行人数 `x/y`（右侧出现的「3/3」「交易所」是背景场景文字，不是 UI）；全局人数只在顶部 `18/18 P`，电力在右上 `1080/1220 kW` +「正常负载 / 电力充裕」。

### 1.2 心情（红脸/绿脸）

- 只在驻员状况面板里显示：每个头像**左下角**一个圆形徽章，绿笑脸 / 红哭脸；主界面建筑上没有心情标记。
- 徽章中心（相对设施名 OCR 框）：
  - 3 槽行：左边 `+344 / +439 / +533`，顶边 `+0`（实测 −3..+3）。
  - 5 槽行（挖掘矿场）：左边 `+157 / +252 / +347 / +442 / +537`。
- 判据用比值（不用 9×9 均值）：
  - 红：`R-G>=50 且 R-B>=30 且 R>=100`
  - 绿：`G-R>=60 且 G-B>=10 且 G>=110`
- 统计口径＝整行徽章圆内红色像素占比；**任一个槽位红即整行算红**（用户规则：哪怕 1 个红也整组换）。
- 实测分布（12 帧 × 4 行，逐槽 RGB 波动为 0）：

| 类别 | 样本 | 红比例 | 绿比例 |
|---|---|---|---|
| 红行 | 36 | 0.619 – 0.654 | 0.000 |
| 绿行 | 12 | 0.000 | 0.469（同值） |
| 红槽 | 132 | 0.494 – 0.889 | 0.000 |
| 绿槽 | 36 | 0.000 | 0.440 – 0.499 |

实跑基线复核（025717 / 030832 / 031410 / 032456）：绿行红比例恒为 `0.000`，绿槽最高 `0.002`（PNG 抗锯齿）；红槽最低 `0.426`。**两类样本在红/绿两个指标上都不交叠**，绿永远不会被判红，`红≥0.30` 无需改判据。

阈值取 `ROW_RED_MIN=0.30`、`SLOT_RED_MIN=0.30`、`ROW_GREEN_MIN=0.25`。

**为什么必须保留槽级 OR（真实漏报案例）**：030832 合成工厂是 3 槽里只有 1 人红，整行 `red_ratio` 只有 **0.289 < 0.30**；若把「整行比例 ≥0.30」当作唯一判据，这个行会被漏掉，而它正是 03:08 那次真实换班的触发源。5 槽设施只红 1 人时整行更低（≈0.17）。所以触发条件是 `任一槽红 OR 整行红比例≥0.30`，**整行比例只能当补充，不能当唯一判据**。

### 1.3 预设

- 每个设施 **4 套预设**，单设施整套、即时生效（≤2s）、无二次确认、无消耗。
- 预设1/2 已配置；预设3/4 显示 `⚠50` 未解锁（**永不点击**）。
- 按钮文案只有两种：`使用`（未在工作）/ `工作中`（当前在用）。
- 弹窗布局：`预设N` 标题在 x≈246，按钮中心 x≈957，行距 185；弹窗一次显示 2 套，可上滑看下一对。
- 点击「使用」后弹窗自动关闭；**重开弹窗**可看到原工作套变 `使用`、新套变 `工作中`。
- 切下来的一组**留在未工作那套**（不自动进宿舍）；重开弹窗仍能看到它们的心情（红脸仍在）。

### 1.4 电力与预设的对应

| 实测场景 | 电力文案 |
|---|---|
| 挖掘矿场 预设1 ↔ 预设2 | **两套完全相同**：`885/1298 kW` 电力充裕 |
| 早期 3 槽设施观察 | 出现过 `885/1220 电力充裕` 与 `1080/1220 正常负载` 两值（未确认是否由预设决定） |

- **结论：电力/负载不是「预设」的稳定指纹。** 2026-11-05 03:00 实跑切挖掘矿场（预设1→预设2），电力前后都是 `885/1298`，没有变化；因此复核②降级为「记录前后值」，不作为失败判据（真正的门禁是①③④）。
- **局限：当前每个设施只有 2 套可用**（预设3/4 是 `⚠50` 未解锁），无法做「同一设施连切 3 个不同预设」的稳定性预验。

### 1.5 心情颜色与数字（11:44 用户截图复核）

- **颜色语义没有反**：同一帧里 `27`（行星指挥部 3 人）上方是红色哭脸徽章（红占比 `0.237–0.248`、绿 `0.000`），`100`（闲置）上方是绿色笑脸徽章（绿占比 `0.410–0.444`、红 `0.000`）。所以 **红=心情低、绿=心情高**，现有「红脸触发」判据方向正确。
- **数字心情值只在「驻员编辑」页面出现**（`驻员上限：3/3` 那个页面，逐卡显示 `27`/`100`）。`驻员状况` 面板与预设弹窗里 **没有数字**（面板帧 OCR 只有电力 `885/1298 kW`、人数 `18/18P`，无心情数字）。
- OCR 实测（`sandbox/_ocr_frame.py` 同一套 MAA OCR）：`100` box `[1010,371,16,11]` score `0.969`、`[1168,371,17,11]` `0.959`；`27` box `[540,370,14,12]` `0.987`、`[697,371,15,11]` `0.991`、`[853,370,16,12]` `0.992`。两位数/三位数都能稳定读出，正负例（27 与 100）分得开。
- 结论：数字可以作为**辅助判据/校验**，但日常链路停在 `驻员状况` 面板，要到数字需要额外打开驻员编辑页（多点一层），因此**默认仍用徽章红/绿**；数字只在需要精确验证时使用。

### 1.6 闲置恢复与两班倒（03:24 → 03:50 → 11:44）

- 02:58 把挖掘矿场从预设1 切到预设2 后，被换下的预设1 变成闲置；03:24 读它仍是 5 枚全红 `0.626/0.488/0.533/0.841/0.562`。
- 26 分钟后（03:50）再读同一套闲置：红占比降到 `0.270/0.249/0.249/0.358/0.245`，绿仍 `0.000`——**闲置 26 分钟已在恢复**，只是还没回到绿色（处于红/黄过渡态）。
- 11:44 用户实测该闲置队已到 `100`（绿脸），而在岗队（02:57 起上班的行星指挥部）掉到 `27`（红脸）。三段证据方向一致：**闲置会恢复、在岗会消耗，两班倒可以循环**。
- 注意：恢复中途徽章红占比会在 `0.30` 阈值附近摆动（`0.245–0.358` 跨阈值），单帧判定可能抖动；8 小时周期下每次只看一次，影响可接受，但登记为 P-045。

### 1.7 宿舍

- 最后一行，普通行，**没有「驻员预设」按钮、没有心情徽章**。
- 面板标 `0/10`，但**可用槽位只有 5 个**（只显示 5 个 `+`）。
- **结论（用户 2026-11-06 确认，已知设计）**：另外 5 个位置**不放人、也不恢复体力**，属游戏设计而非显示问题，**无需再实测**「第 6–10 槽」。问题登记见 P-041（已按「登记为例外」收口）。
- 横向滑动（`input swipe 900 581 400 581 400`）后画面无变化：5 个可见槽不横向滚动；03:11 复看（滚到底 + 行内 `swipe 900 465 → 400 465`）两帧完全一致，佐证无隐藏槽。
- 对实现的影响：换班逻辑**不得假设 10 个可用槽**（按 5 槽设计）；宿舍**只能人工换人**（一次换一行），不实现自动换人，也不自动往宿舍塞人。

## 2. 已落地实现

### 2.1 模块拆分

| 模块 | 职责 | 入口 |
|---|---|---|
| `agent/infra_mood.py` | 触发模块，只回答「谁要换」：OCR 设施名框作行锚点 + 相对偏移量整行红色占比 | `measure_frame` / `measure_row` / `needs_shift` |
| `agent/infra_shift.py` | 执行模块：整组切「没在工作那套」+ 四层复核；宿舍人工换人骨架（禁用） | `infra_shift` / `infra_manual_swap` |

### 2.2 节点清单

| 节点 | 实现 | 入口 OCR / 定位 | 判据 |
|---|---|---|---|
| `基建_驻员状况` | 打开面板后 → `基建_换班门禁` | OCR「驻员/状况」 | 识别到面板即进入周期门禁 |
| `基建_换班门禁` | Custom `task_memory_gate`（`task=基建换班检测`、`cooldown_minutes=480`） | DirectHit | 距上次**检测**满 8 小时放行，否则跳 `基建_换班_未到点` |
| `基建_换班` | Custom `infra_shift` | 设施名 OCR 框（左列 roi `[300,60,170,620]`）→ 槽位相对偏移 | 红脸触发 + 四层复核，见 2.3 |
| `基建_换班_检测完成` | Custom `task_memory_complete`（同参数） | DirectHit | 巡检（全绿或已换班）通过后写检测时间；换班失败不写，不占周期 |
| `基建_换班_未到点` | DoNothing → `基建_返回按钮` | DirectHit | 未到点只关面板，不巡检、不换班 |
| `基建_换班_人工干预` | Custom `infra_manual_swap`，`enabled=false` | 宿舍行 OCR 框 | 骨架，尚无角色选择弹窗点击序列 |
| 原 `基建_驻员预设1~4`、`基建_使用` | **已删除** | — | 裸点击链：只点「预设」再点任意「使用」，无幂等/无复核 |

删除理由：这 4 个节点是主链路上的中途裸点击，既不看红脸也不做任何验证，且会点到 `⚠50` 之外的任意 `使用`；合并成参数化自定义动作后才能保证「红脸触发 / 幂等 / 分层复核 / 永不点 ⚠50」。

扫描健壮性（P-042）：`_scroll_to_top` 以 OCR 看到「行星指挥部」为到顶标志；**一次读空不等于不在面板**——连续 3 次（间隔 0.5s）都读不到才认定不在面板，`_scan_panel` 整轮再重试 3 次。入口前置条件是游戏停在**基建主页**并由 `基建_驻员状况` 点开面板；直接以 `基建_换班` 作入口时必须面板已打开。单节点验证可用 `tools/run_task.py --override '{"基建_换班":{"next":[]}}'` 截断链路，避免跑到后面的交易/交付分支。

### 2.3 四层复核（①③④任一不过 → 存图 + 停止；②只记录）

1. **面板内**：重开预设弹窗，目标按钮 `使用`→`工作中`，原工作按钮 `工作中`→`使用`。
2. **面板外（降级为记录）**：记录顶部电力/负载前后值；实测同设施两套预设可能完全同功耗（挖掘 885/1298），所以「未变化」不判失败，变化则记录为辅助信号。
3. **整组绿脸**：切完等 2.5s 再抓，重新定位该设施行，整行不得再有红脸。
   **例外（2026-11-13 用户定）**：单槽设施 `合成工厂` 只有 1 名驻员，其心情由一次合成操作瞬时消耗，红脸是正常工作态、不代表换班失败。因此该设施的红脸**不判失败、不触发 30 分钟重试**：复核③只写 WARN（`warn_red_left_合成工厂.png`）并继续下一个设施；仍保留「红槽数意外上升 → 失败」这条真判据。其它多槽设施的判据不变。
4. **误伤**：其他设施可见槽位数/红绿态、全局人数（`x/x P`）不得变化。同一轮切过多个设施时，**本轮已切设施不参与比对**（否则会把自己刚切好的行当成误伤，P-043）。

### 2.4 候选规则与幂等

- 目标 = 弹窗里文案为 `使用` 的预设；`工作中` 跳过；`⚠50` 永不点击。
- 多套候选时优先「心情全绿」那套：读弹窗头像徽章（只取徽章圆，红发角色不干扰）。3 槽偏移相对「预设N」标题框 `+23/+146/+267, dy=125`；5 槽实测 `+24/+160/+288/+412/+546, dy=128`。读不到头像时按第一条 `使用`。
- 只有一套已配置（没有任何 `使用`）→ 报「无可换预设」并跳过该设施，不切别的设施。
- 目标是 `工作中`（已生效）→ 直接算通过，不重复点。
- `interface.json` 选项「基建_换班预设覆盖」可逐设施指定目标预设（JSON，如 `{"行星指挥部":1}`）；留空＝默认行为。

### 2.5 只读巡检（`infra_idle_probe`，仅测试用）

用来回答「闲置那套的红脸会不会自己变绿」：工作套的脸在面板里，闲置套的脸只在预设弹窗里。巡检只做四件事：扫面板 → 定位目标设施行 → 点开其预设弹窗（`使用`/`工作中`/锁定 + 每枚头像徽章的红绿占比）→ 按返回键关窗。**不点 `使用`、不点 `⚠50`**，不产生游戏状态变更。输出 `sandbox/red_baseline/idle_probe_<时间戳>.json` 与弹窗截图。只在 `tools/run_task.py --with-agent` 里注册，不进生产 agent。

### 2.6 强制预设（`infra_force_preset`，仅实验用）

用于量化「在岗心情消耗速率」与「闲置心情恢复速率」。按 `custom_action_param` 的 `{"facility":"挖掘矿场","preset":1,"wait_seconds":0}` 执行：扫面板 → 切换前后各开一次弹窗读全部预设头像 → 点目标套的 `使用` → 可选等待 → 再扫一次并读弹窗，结果写 `sandbox/red_baseline/force_preset_<时间戳>.json`（含 `row_before/row_after`、`presets_before/after`）。

- 预设在 `工作中` → 幂等跳过，不重复点。
- 预设带 `locked`（`⚠50`）→ 直接失败返回，**永不点击**。
- 同样只注册在 `tools/run_task.py`，不进生产 agent；实验只碰挖掘矿场，不点 `⚠50`、不买、不进宿舍。

### 2.7 8 小时检测周期（复用任务记忆门禁）

- 规则：距**上次检测**满 `480` 分钟才跑下一次；首次运行（无记录）立即放行。换班失败不写检测时间，因此不会白占一个周期。
- 复用 `agent/task_memory.py` 的 `task_memory_gate` / `task_memory_complete`，任务名 `基建换班检测`；状态落在 `config/task_memory/<实例>.json`，重启/换会话不丢。
- 配置：默认值写在 `基建_换班门禁` 的 `custom_action_param.cooldown_minutes`（480）。不想改 pipeline 时，用 `config/task_memory/<实例>.policy.json` 覆盖：
  `{"基建换班检测": {"cooldown_minutes": 480}}`（任务级覆盖；也支持全局 `{"cooldown_minutes": 480}`）。
- 日志三态（`logs/infra_shift.log` + `logs/task_memory/events.jsonl`）：
  1. 未到点跳过 → 门禁返回 fail，日志含「冷却未到期」，进 `基建_换班_未到点`（不巡检、不换班、不写检测记录）。
  2. 到点但全绿 → `巡检通过：全部绿脸，无需换班（到点检测，不切预设）`，随后 `基建_换班_检测完成` 写检测时间。
  3. 到点且有红脸 → 正常的「切预设 + 四层复核」日志，成功后同样写检测时间。

## 3. 未覆盖 / 限制

- 宿舍：面板标 `0/10`，**可用槽位 5 个，另外 5 个位置不放人也不恢复体力**（用户 2026-11-06 确认，已知设计，见 P-041）；不实现自动换人/自动塞人。
- 宿舍人工换人只保留了定位骨架，角色选择弹窗点击序列未实测，节点禁用。
- 同一设施只有 2 套可用，电力↔预设的稳定映射只验证了 1↔2 两值。
- 误伤检测只覆盖切换时**当前视口可见**的其他设施行；视口外的行不参与比对。
- 红脸是否随时间自行恢复（不工作那套）用 `sandbox/red_baseline/red_baseline_<时间戳>.json` 留证，40–60 分钟复看。

## 4. 换班链现状与旧链下线（2026-11-07）

### 4.1 现行主链＝驻员预设方案

- 节点链：`基建_驻员状况` → `基建_换班门禁`（`task_memory_gate`，480 分钟）→ `基建_换班`（Custom `infra_shift`）→ `基建_换班_检测完成`；未到点走 `基建_换班_未到点` → 返回。
- 换班动作由 `agent/infra_shift.py` 按 `facility / preset / wait_seconds` **整组切预设**并做四层复核（见 2.3），全程只操作「驻员状况」面板与预设弹窗，**不依赖任何「设施详情」页**。
