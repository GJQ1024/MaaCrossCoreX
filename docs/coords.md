# 坐标规范（第一版）

本项目的坐标层与上游 MCC_Framework / MCCA 的「固定 ROI + 绝对 target」写法不同，
统一遵守以下规则。`tools/validate_resource.py` 会把规则 4 作为硬性检查。

## 1. 720p 归一化画布

- 所有 `roi`、模板图均以 **1280×720** 画布书写，框架运行时按比例映射到真实截图。
- 强制客户端为 16:9（1280×720 或 1920×1080）；20:9 等拉伸比例不支持。
- 模拟器侧用 `adb shell wm size 1280x720` 调整（可还原，调整前记录原值）。

## 2. 点击位置：识别结果优先

- 默认不写 `target`，即点击识别框中心（OCR 文本框 / 模板匹配框），天然相对。
- 禁止照抄上游的绝对 `target`（如 `[620,350,20,20]`、`[847,527,51,16]`）。

## 3. Anchor + target_offset

需要点击「识别目标之外」的位置时，两种方式（优先 a）：

a. **自身识别框 + `target_offset`**：偏移量相对识别框，布局整体平移时仍正确。
   例：`重连网络/网络不稳定` 以 OCR 文本框为基准偏移 `[166,118,0,0]` 点「确认」；
   `启动游戏/首页标志2` 以活动图标为基准偏移 `[461,-165,0,0]` 点屏幕中部空白。

b. **全局锚点**：`"anchor": "主界面"` 在识别命中后记录节点框（见 `首页标志1`、
   `通用_确认主界面`），后续节点用 `"target": "[Anchor]主界面"` + `target_offset` 引用。
   例：`领取奖励/邮件` 以主界面锚点偏移 `[63,-605,0,0]` 点右上角邮件图标。
   注意：锚点未设置时动作失败，因此引用锚点的节点必须保证上游先设置锚点
   （`领取奖励` 入口先走 `领奖_锚点检查`）。

## 4. 滑动与绝对坐标

- `Swipe.begin` / `Swipe.end` / `MultiSwipe.starting` / `TouchDown.target` 的类型都是
  `true | 节点名 | "[Anchor]锚点名" | 坐标`；锚点/节点形态可再叠
  `begin_offset` / `end_offset` 做相对偏移；`Swipe.end` 支持列表（多段折线，不抬手）。
  `TouchDown` / `TouchMove` / `TouchUp` 自 MaaFramework v5.0 起就是 JSON 动作。
- **滑动优先用「识别锚点/节点名 + offset」**：例如以列表容器或卡片为锚点，
  `begin` 取锚点 + `begin_offset` 定起点，`end` 用相对位移；不要写死两端像素。
- 只有**连锚点都识别不到**的极端情况才用绝对坐标，且必须集中在少数节点、
  在下方例外清单逐条登记原因。`tools/validate_resource.py` 对数组形式的
  绝对 `target` 做硬性检查（仅限 MIGRATED_FILES）。
- 真实存在的限制：pipeline JSON 没有百分比/表达式语法，坐标只能写字面量。
  需要「运行时读识别结果再算坐标」的场景，用 Agent 自定义动作
  （`run_recognition` 取结果 → 算坐标 → `post_swipe` / `post_touch_*`）；
  输入后端用框架内置 MaaTouch（优于 AdbShell），不用额外接。

### 例外清单（绝对坐标登记处）

> 本清单登记**有意保留**的绝对坐标。判定顺序：先看能否「点识别框中心」，再看有无稳定锚点；
> 两者都不成立才落到这里。识别参数（roi / template / threshold / expected）一律未改。
> 批 4 新增的 `target_offset` 均为**离线按识别框左上角推算**（识别框实际落点需实机校准），
> 滑动位移取自原 begin/end 差值；上真机后若有 10px 以上偏差，按实机结果修正数值。
> 批 5 起，「无副作用空白点击」不再写数组 `target`：保留 `DirectHit`，把原 4×4 点位写成
> `roi` 并删 `target`，点击走识别框中心（与 `新手教程_安全区盲点` 同范式，中心与原坐标一致）。
> 购买/消耗/抽卡/确认类点击一律不允许用这种方式，仍按绝对坐标登记。
> 批 5 收尾决策：①`基建-订单库` **功能未接入**（`base_order_state` 未注册、非 interface 入口），不接线，15 处坐标照旧保留；②`alien_shop_*` 命中时返回 `box=(0,0,0,0)` 属**缺陷**，正确约定是无框回 `None`（与 `arena_pipeline` 一致），后续统一修；③`activity_state` / `daily_stamina_state` 只回会话状态，迁移前需**新增 OCR 探针**。剩余绝对坐标最终对账见 `specs/coords-batch5/最终对账表.md`。
> **新增硬条款（2026-11-02）**：本清单中的 roi / target / target_offset 以及所有模板图，一律必须取自
> adb 原始分辨率（1280×720）的实机截图，并在提交信息或节点注释标注来源截图；
> 「按比例换算」「凭经验推算」出来的值只能标 `TODO(待实机校准)`，不得作为最终值、不得进入主线。

> **竞技场撤退语义（2026-11-03 实测，可直接用）**：撤退确认框明写「**不扣除战斗次数**」——
> 撤退与失败都不消耗挑战次数，失败分支可放心走，不必为省次数强行打完。

### 横滑锚点写法（列表滑动范式）

可滚动列表（卡片/关卡/商品）的 Swipe **不写死两端绝对像素**，
统一用「列表内任一卡片识别节点 + offset」：

```json
"每日探索_芯片卡片识别": {
    "recognition": "OCR",
    "roi": [790, 90, 350, 535],
    "action": "DoNothing",
    "timeout": 3000
},
"每日探索_芯片列表归顶": {
    "recognition": "DirectHit",
    "action": "Swipe",
    "begin": "每日探索_芯片卡片识别",
    "begin_offset": [0, 0, 0, 0],
    "end": "每日探索_芯片卡片识别",
    "end_offset": [0, 380, 0, 0],
    "duration": 600
}
```

要点：

- **锚节点**：OCR/Template 识别列表内任意一张卡片文字或图案，`action: DoNothing`
  （只识别不点击）。roi 与列表可视区一致，不设 `expected` 即命中"best"，
  无论命中哪张卡都不影响滑动位移。
- **Swipe begin/end 都引用同一锚节点**：`begin = 锚`、`begin_offset = [0,0,0,0]`
  （从锚框左上角起），`end = 锚`、`end_offset = [0, Δy, 0, 0]`（固定位移）。
  Δy 的正负决定方向：归顶向下拖（+Δy）、往下翻向上拖（-Δy）；横向同理用 Δx。
- **禁止形态**：`"begin": [x, y, w, h]` + `"end": [x, y, w, h]` 两端绝对像素，
  即使归一化后稳定也属于硬编码（`validate_resource.py` 对 MIGRATED_FILES 报错）。
- **退化场景**：连一张卡片都识别不到（如列表为空、加载失败），才允许
  退化为绝对坐标，且必须登记到 §4 例外清单含原因。

## 5. 每个识别节点必须

- `pre_wait_freezes: {time: 1000, threshold: 0.95}`（等弹窗/过场动画稳定）；
- 合理的 `timeout`（主线 10–60s，子任务 1s，入口 60–180s）；
- 失败兜底：入口节点 `on_error` → `重连网络`，链路节点必要时回 `子任务_进入首页`。

## 6. 命名

- 节点名统一中文，不中英文混排；子任务（可被 JumpBack 复用的弹窗处理）加前缀 `子任务_`；
- 上游英文名节点已汉化：`Shop→补给站_进入`、`DailyGift→礼包_每日免费`、
  `DailyGiftYes→礼包_免费`、`Purchase→礼包_购买`、`Mail→邮件` 等。

## 7. 如何加新节点

1. 截图（720p）→ 裁剪模板放入 `assets/resource/image/`，登记 `docs/assets-source.md`；
2. 在对应 pipeline 文件加节点，遵守 §2/§3/§5/§6；
3. 跑 `tools/validate_resource.py`，全绿后才允许提交。

## 8. 迁移边界决策

- **编队九宫格：不迁移。** 理由：游戏支持多套编队、扫荡可选队，用户手动配一次即可；
  并非「拖拽做不到」（`TouchDown/Move/Up` 自 v5.0 起就是 JSON 动作，技术上可实现，只是不值）。
- **基建换班：可进第二版。** 用「点槽位 + 长滑列表 + 点干员」三步即可覆盖，
  不需要拖拽；长滑按 §4 用锚点 + offset。
- 拖拽类操作整体不进 pipeline；确有需要时走 Agent 自定义动作（§4）。
